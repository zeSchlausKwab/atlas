02 / End to end

From source facts
to useful answers.

Rust handles native import and the rendering/routing cores. Bun and TypeScript coordinate preparation, storage, delivery and tools. The browser owns the interactive map and local computation.

Pin the source, then choose the area.

Use a cached planet PBF, a regional download or a compatible existing Atlas archive. Record the exact source fingerprint. A PBF is scanned and extracted locally; it is not geographically queryable through arbitrary byte ranges. Sea polygons come from a separately identified coastline dataset.

03 / What you can do

A map you can
work with.

Capabilities describe what a package contains. They are optional at preparation time. A tiny visual asset and an analysis-rich regional map use the same container.

▧

Render & style

Separate water, landscape, building, road and rail layers. Independent place, street and POI labels. Color and width controls, pitch, bearing and building extrusion.

Zoom to 20 by overzooming the highest stored vector tiles. OSM height tags and floor estimates are distinct from unknown height; there is no terrain elevation in building extrusion.

Route & explore reach

Find places & addresses

04 / Maps as tools for intelligence

The model asks.
The client does the work.

Instead of sending thousands of coordinates through a model, Atlas gives it tool schemas and references to data held on the device. The geographic work stays grounded in retained source objects.

“Show 100, 250 and 500 metre bands along the Danube’s mapped banks. Exclude water, find buildings in each band, and colour them by height.”

Ground the request in a place

Resolve names and actual geometry. The camera is context, not an automatic analysis boundary. “Here” and “current view” opt into it.

Keep the expensive work

A prepared workspace pins selected data. Follow-up filters, geometry operations, colours and contours reuse local results.

Make the work inspectable

Tool arguments, responses, progress, timing, package reads, drawings and charts are visible. Export the conversation as JSON for evaluation.

Example tool workflowOn this device
  1. object_search · object_get

    Find the named water features and inspect their retained footprints and provenance.

  2. workspace_prepare · workspace_query

    Apply area and tag filters, fetch necessary pages, and keep geometry under local result IDs.

  3. spatial_bands · spatial_filter

    Construct dissolved, disjoint distance bands; identify buildings intersecting them.

  4. result_summary · result_style

    Count known and unknown heights. Assign colours, labels and a legend.

  5. map_draw · chart_show

    Draw the referenced geometries and explain the result with its geographic limitations.

Conceptual sequence, not a recorded run. Bands measure proximity to mapped geometry, not flooding or travel time.
Browser / local data plane

Readers → workers → results → map

Verified blocks, Rust/WASM routing, spatial operations and a QuickJS sandbox. Custom JavaScript gets selected JSON data; no network, DOM or filesystem access.

⇄
Online / model inference

Agent → credential proxy → model

The demo uses DeepSeek Flash. The proxy keeps the API key out of the browser; prompts and tool evidence go to the model. Inference still needs a connection.

Local map computation and online inference are separate. Cached analysis can run without the map provider, but that does not make the model offline or prevent selected facts from appearing in its tool responses. Read the AI execution contract ↗

05 / More than one host

Different sources.
One working map.

Nostr tells a consumer what a publisher offers. Hashtree identifies and verifies the bytes. Atlas explains what those bytes mean and whether they can work together.

01

Discover the offer

A signed Nostr event advertises a pinned map root, capabilities, coverage and delivery endpoints. Consumers explicitly choose publishers.

02

Fetch and verify

Hashtree uses SHA-256-linked chunks. The host serves them from the original file. Same-root mirrors can supply the same bytes; the client caches verified content.

03

Compose by meaning

Visual layers can overlap. Cross-map routing additionally checks source authority, transport policy, stable OSM identities and complete cell coverage.

04

Expose the gaps

Missing cells remain missing data, not “no road.” Coverage review supports acquiring an area on the host or saving source blocks in the browser.

Independent build, compatible source. Current federated routing requires the exact same upstream PBF fingerprint and transport contract. It does not require a common compiled Atlas parent. Different OSM dates or independently dated regional downloads are not automatically routable together. Matching coordinates alone never create a junction.

Save on the device

Pin an area’s verified source blocks outside the rolling cache. Reuse them for display, routing and AI. This is persistent browser storage, not a newly portable archive or a guarantee of fully disconnected app startup.

Acquire on the host

The server can act as a consumer, review coverage and fetch from peers. Its export packs one or more self-contained members into a single .atlas, with no external map dependency at runtime.

Today’s network data channel is HTTP Hashtree blobs. Nostr carries announcements and, when configured, ContextVM tool messages. Automatic peer-to-peer seeding, WebRTC delivery and arbitrary cross-revision routing remain future work.

Compose at viewing time

Read separate vector and raster Atlas sources in one scene. Each keeps its own root, attribution and update cycle. A published view captures their composition.

Combine for portability

Embed imagery or source members in one output archive. This costs copying and storage, but the final file carries its data with it. Current amendments rewrite a file rather than append in place.

New code does not always need new map data. A plugin that ranks retained lake polygons can run over an existing archive. A tool requiring unretained depth, terrain or timetables needs a new source, schema and build step. Operation names alone do not define geographic meaning.

07 / The honest boundary

Working today.
Room to explore.

This is an end-to-end experiment with real files and executable proofs. It is also an evolving format: scalable storage and explicit correctness contracts matter as much as a convincing map.

Implemented

The current foundation

  • Local Bun host and independent browser client; no remote Atlas service is required.
  • Selective vector, label, raster, graph and semantic reads with verification and caching.
  • Server and device navigation, search, extraction; browser AI analysis and drawings.
  • Signed discovery, Hashtree transport, compatible cross-source routing and area acquisition.
  • Queued builds, progress, resumable stage checkpoints, amendments and file imports.
  • NAS-assisted builds: sequential bulk payloads can use extra storage; mutable indexes stay local.
Not yet a product promise

The remaining frontier

  • A finalized, stable format specification and polished native mobile/desktop SDKs.
  • Proven planet-scale throughput and predictable build-time, memory and disk requirements.
  • General routing between different OSM revisions, global shipping and time-dependent networks.
  • Numeric terrain, bathymetry, population, weather, hazard data and their analysis contracts.
  • General GPU raster rendering, arbitrary reprojection and a portable plugin ecosystem.
  • Seamless disconnected startup in every workflow, automatic relay renewal and peer seeding.

Data completeness, source revision, execution location and measurement semantics belong in results. A verified hash proves which bytes arrived; it does not prove a map is complete or an analysis is scientifically valid. Host-side capability switches govern serving and computation, not copies already downloaded.

08 / Take it for a walk

Start small.
Run it locally.

From a clone of this repository, setup builds a small Liechtenstein sample with display, routing, search and selectable data. Dependencies and the initial extract need internet; no LAN server, account or planet download is required.

Prerequisites: Bun 1.3+, stable Rust/Cargo, wasm-pack and a native C/C++ toolchain. macOS and Linux; WSL2 for Windows. Arbitrary PBF extraction in the host console also needs osmium-tool.
